# Lab Start / Stop Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Lab tab (renamed Cleanup) with Start lab / Stop lab as jobs (graceful shutdown/start in order, FortiFlex licences stopped/reactivated by the serial remembered in each VM's notes) next to the existing Delete.

**Architecture:** Deployment writes `licence=<serial>` into every VM's Proxmox notes. A new `app/lab.py` holds the pure parts (inventory with roles and order, prefix, licence matching) and the two job flows (`stop`, `start`) on top of `pve` and a FortiFlex client; `app/main.py` adds `/api/lab/*` endpoints that run them as ordinary jobs with their own step list; the UI renames Cleanup to Lab.

**Tech Stack:** FastAPI, Proxmox API (`app/pve.py`), FortiFlex (`app/fortiflex.py`), vanilla JS; script-style tests in `tests/`.

**Spec:** `docs/superpowers/specs/2026-11-27-lab-power-design.md`

## Global Constraints

- Lab = tool-tagged VMs/CTs on the chosen node, same filter as `app/cleanup.py:plan` (deploy container excluded).
- Stop order: clients + Traffic-Gen → FortiGates → wan-emu → FortiManager(s); Start order: the reverse.
- Graceful shutdown (`POST …/status/shutdown`), hard stop after 180 s (FortiManager 300 s); already in the target state = skipped.
- Licences: serial from VM notes (`licence=<serial>`); fallback name match only for VMs without it, marked `source: "name"`; jobs get only the serials the user ticked. Stop acts on ACTIVE/PENDING, Start on STOPPED; others shown and skipped. Never create a licence or a token.
- Prefix = wan-emu CT name minus `wan-emu` ("" without wan-emu).
- Jobs: ordinary jobs (store, stream, Cancel), `steps_def` per kind — stop: `shutdown`, `licences`; start: `licences`, `start`, `check`. One global lock with deploy and cleanup.
- Failures: per guest logged, job goes on, ends `done` with warnings; Cancel stops after the current guest (cancellable waits) and skips Stop's licence step.
- Tab: label **Lab**, route `#/lab`, `#/cleanup` alias.

## Review Focus

1. A lab where some VMs are already stopped (Stop) or running (Start) → those are skipped, the rest proceeds. (Task 3 test.)
2. A guest that ignores shutdown → hard stop after the timeout, job continues. (Task 3 test with a fake that never stops.)
3. Two licences with the same device name in different ADOMs and no notes → both shown as `name`, nothing acted on unless ticked. (Task 2 test.)
4. FortiFlex not configured or licence-file mode → no licence steps, overview says so, Start/Stop still work. (Task 3 test.)
5. A deployment started while a lab job runs (and vice versa) → refused with 409. (Task 4 test.)
