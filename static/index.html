WAN emulation (LXC wan-emu, always deployed with FortiGate VMs)

The container routes between ISP-HUB (hubs, static IP), ISP-A (spoke wan1) and ISP-B (spoke wan2), gives the spokes a DHCP reservation and NATs to the lab via the uplink. The WAN emulator bridge carries the ISP segments, the FortiGate WAN/LAN ports and the LAN clients (an internal VLAN-aware bridge is ideal); the uplink bridge connects wan-emu to your lab. Set latency, jitter, loss and bandwidth per link on the WAN emulation page.

Enter the serial number and FortiFlex token per FortiGate below (or let FortiFlex fill them in). Hubs have one WAN (wan1, static IP + gateway); branches use wan1 and optionally wan2, always via DHCP. Every branch WAN gets a tunnel to wan1 of every hub. The tool creates the VMs with Day-0 (cloud-init) on Proxmox: IP, password, FMG link and token go into the config drive.

    About
    
      
    
        
    01What does this tool do?
    
        
    Deploys an SD-WAN/ADVPN topology through FortiManager 8.0 (hubs and branches in one region, single- or multi-VRF). The tool creates native templates in FortiManager (metadata variables, system, SD-WAN and CLI templates, policy packages, template groups and blueprints), derived from Fortinet's Orchestrator — no Jinja in FortiManager. It can also create the VMs on Proxmox (Day-0 with FortiFlex) behind an emulated WAN, or bootstrap existing VMs over SSH.
